**Итог:**

 - Механизм развёртывания реализован через конфигурацию docker-compose.yml: SQL‑скрипты sakila-schema.sql (структура) и sakila-data.sql (данные) смонтированы в специальную директорию контейнера /docker-entrypoint-initdb.d/.Данная директория является штатной точкой входа для инициализации образа mysql:8.0: при первом запуске контейнера и отсутствии инициализированной базы данных встроенный entrypoint‑скрипт автоматически обнаруживает и последовательно выполняет все скрипты из этой папки.
- Порядок инициализации строго соблюдён: сначала был применён скрипт создания схемы (1_schema.sql), что позволило сформировать таблицы, внешние ключи и индексы; затем — скрипт наполнения данными (2_data.sql), который добавил записи в таблицы. Такой подход гарантирует целостность связей и отсутствие ошибок при вставке данных из‑за отсутствия родительских записей.
- Таким образом, восстановление дампа произведено штатными средствами Docker без использования ручных команд импорта (source/LOAD DATA). Структура и наполнение базы полностью соответствуют эталонной схеме sakila. Механизм /docker-entrypoint-initdb.d/ обеспечил надёжную и воспроизводимую инициализацию базы данных в контейнеризированной среде.

# Задание 2

Составьте таблицу, используя любой **текстовый редактор** или **Excel**, в которой должно быть два столбца: в первом должны быть названия таблиц восстановленной базы, во втором названия первичных ключей этих таблиц. Пример: (скриншот/текст)

```
Название таблицы | Название первичного ключа
customer         | customer_id

```

## Ответ:

```
SELECT
  TABLE_NAME,
  GROUP_CONCAT(COLUMN_NAME ORDER BY ORDINAL_POSITION SEPARATOR ', ') AS PRIMARY_KEY
FROM information_schema.KEY_COLUMN_USAGE
WHERE TABLE_SCHEMA = 'sakila'
  AND CONSTRAINT_NAME = 'PRIMARY'
GROUP BY TABLE_NAME
ORDER BY TABLE_NAME;
```

![alt text](<Screenshots/Задание 2-1.png>)

**Итог:**
- Получен список всех таблиц схемы sakila с их первичными ключами в двухколоночном формате.
- Составные первичные ключи (для film_actor, film_category) агрегированы в одну строку через запятую за счёт GROUP_CONCAT.
- Данные отсортированы по имени таблицы (ORDER BY TABLE_NAME).

## Задание 3*

3.1 Уберите у пользователя **sys_temp** права на внесение, изменение и удаление данных из базы **Sakila.**
3.2 Выполните запрос на получение списка прав для пользователя **sys_temp.** (скриншот)

*Результатом работы должны быть скриншоты обозначенных заданий, а также простыня со всеми запросами.*

## Ответ:

```
- docker exec -it sakila-mysql mysql -uroot -p

- REVOKE ALL PRIVILEGES, GRANT OPTION FROM 'sys_temp'@'localhost';  - Полный отзыв всех привилегий
- FLUSH PRIVILEGES;

- GRANT SELECT ON sakila.* TO 'sys_temp'@'localhost';  - Выдача только права SELECT для базы sakila
- FLUSH PRIVILEGES;

- SHOW GRANTS FOR 'sys_temp'@'localhost';   - Проверка итоговых прав
```

![alt text](<Screenshots/Задание 3-1.png>)

 *Подтверждение блокировки записи - выполняется под пользователем sys_temp:*
```
- docker exec -it sakila-mysql mysql -usys_temp -p
- INSERT INTO sakila.actor (first_name, last_name) VALUES ('Test', 'Actor');  - Попытка INSERT — должна завершиться ошибкой (доказательство отзыва прав)
- SELECT COUNT(*) FROM sakila.actor;  - Проверка SELECT — должна выполниться успешно (доказательство, что чтение осталось)
```

![alt text](<Screenshots/Задание 3-2.png>)

**Итог:**
- Под root отозвали все привилегии у sys_temp командой REVOKE ALL PRIVILEGES… — пользователь остался только с правом подключиться (USAGE).
- Дали ему строго ограниченное право: только SELECT на базу sakila.
- Проверка SHOW GRANTS подтвердила: в правах нет INSERT/UPDATE/DELETE/DROP/ALTER — только USAGE ON *.* и SELECT ON sakila.*.
- Тестовый INSERT под sys_temp выдал ошибку ERROR 1142 — запись реально заблокирована.
- SELECT COUNT(*) под sys_temp отработал — чтение работает.
-  У sys_temp нет прав на внесение, изменение и удаление данных в sakila, но есть право на просмотр.
